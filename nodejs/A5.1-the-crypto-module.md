## Goal
Use `node:crypto` correctly for the everyday security primitives — hashes, message authentication, random tokens, and safe comparisons — and know which primitive solves which problem.

## Background

### Which primitive for which job
| Need | Primitive | API |
|------|-----------|-----|
| Fingerprint / integrity check of data | Hash (SHA-256) | `createHash('sha256')` |
| Prove a message came from someone holding a secret, unmodified | HMAC | `createHmac('sha256', key)` |
| Store passwords | Slow, salted KDF (scrypt, argon2, bcrypt) | `scrypt` (A5.2) |
| Keep data secret | Authenticated encryption (AES-256-GCM) | `createCipheriv` (A5.3) |
| Unpredictable tokens, IDs, keys | CSPRNG | `randomBytes`, `randomUUID`, `randomInt` |
| Signatures verifiable with a public key | Ed25519 / RSA / ECDSA | `sign` / `verify` |

### Hashes
A cryptographic hash maps any input to a fixed-size digest. It's deterministic, a tiny input change produces a completely different digest, and it's infeasible to find an input for a given digest. Use **SHA-256** or **SHA-512**; **MD5 and SHA-1 are broken** for security purposes (fine only for non-adversarial checksums). A plain hash is **not** suitable for passwords — it is designed to be fast, so attackers can try billions of guesses per second.

### HMAC
A hash alone proves nothing about who produced it — anyone can hash data. An **HMAC** mixes in a secret key: only someone with the key can produce a valid tag. Webhook signatures (Stripe, GitHub), signed cookies, and JWT HS256 all use HMAC.

### Randomness
`Math.random()` is **not** cryptographically secure — its output can be predicted. For tokens, session IDs, reset links, API keys, salts, and IVs, use `crypto.randomBytes(n)`, `crypto.randomUUID()`, or `crypto.randomInt(min, max)`. 32 random bytes (256 bits) is a good default for secrets.

### Constant-time comparison
`a === b` on secrets leaks information through timing: it stops at the first differing character, so an attacker can measure response times to guess a token byte by byte. Use `crypto.timingSafeEqual(bufA, bufB)` — but it requires equal-length Buffers, so check lengths (or compare fixed-length digests) first.

### Web Crypto
`globalThis.crypto.subtle` implements the browser's Web Crypto API (async, promise-based). Use it when code must run in both Node and browsers or edge runtimes; otherwise the `node:crypto` API is simpler.

### 1. Hashing strings and files

```bash
mkdir a5-1-crypto && cd a5-1-crypto
npm init -y && npm pkg set type=module
```

```js
// hash.js
import { createHash, hash } from 'node:crypto';
import { createReadStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';

const sha256 = (data) => createHash('sha256').update(data).digest('hex');

console.log(sha256('hello'));
console.log(sha256('hellp'));                       // completely different (avalanche effect)
console.log(sha256('hello') === sha256('hello'));   // deterministic
console.log(createHash('sha256').update('hel').update('lo').digest('hex') === sha256('hello'));  // incremental

// One-shot helper (Node 21.7+) for small inputs
console.log(hash('sha256', 'hello'));

// Stream a file through a hash
const h = createHash('sha256');
await pipeline(createReadStream('package.json'), h);
console.log('package.json sha256:', h.digest('hex'));
```

Compare with the shell: `shasum -a 256 package.json`.

### 2. HMAC: sign and verify a webhook

```js
// webhook.js
import { createHmac, timingSafeEqual } from 'node:crypto';

const SECRET = 'whsec_test_secret';

export function sign(payload, secret = SECRET) {
  return createHmac('sha256', secret).update(payload).digest('hex');
}

export function verify(payload, signatureHex, secret = SECRET) {
  const expected = Buffer.from(sign(payload, secret), 'hex');
  const received = Buffer.from(signatureHex, 'hex');
  return received.length === expected.length && timingSafeEqual(received, expected);
}

const body = JSON.stringify({ event: 'payment.succeeded', amount: 4200 });
const sig = sign(body);
console.log('signature:', sig);
console.log('valid:', verify(body, sig));
console.log('tampered body:', verify(body.replace('4200', '1'), sig));
console.log('wrong secret:', verify(body, sign(body, 'attacker-guess')));
console.log('garbage signature:', verify(body, 'abc'));
```

### 3. A webhook receiver that verifies the raw body

```js
// receiver.js
import { createServer } from 'node:http';
import { verify, sign } from './webhook.js';

createServer(async (req, res) => {
  const chunks = [];
  for await (const c of req) chunks.push(c);
  const raw = Buffer.concat(chunks);                       // verify the exact bytes, not re-serialised JSON
  const sig = String(req.headers['x-signature'] ?? '');

  if (!verify(raw, sig)) {
    res.writeHead(401).end('invalid signature\n');
    return;
  }
  console.log('verified event:', JSON.parse(raw).event);
  res.writeHead(204).end();
}).listen(3000, () => {
  const body = '{"event":"order.created"}';
  console.log(`curl -i localhost:3000 -d '${body}' -H 'x-signature: ${sign(body)}'`);
});
```

Explain why parsing the JSON and then re-stringifying it before verifying would be a bug.

### 4. Secure random values

```js
// random.js
import { randomBytes, randomUUID, randomInt } from 'node:crypto';

console.log('API key:', `sk_${randomBytes(24).toString('base64url')}`);
```

### 5. Measure why timing-safe comparison matters

```js
// timing.js
import { timingSafeEqual, randomBytes } from 'node:crypto';

const secret = randomBytes(32).toString('hex');
const wrongEarly = 'x' + secret.slice(1);
const wrongLate = secret.slice(0, -1) + 'x';

function time(fn, n = 2_000_000) {
  const start = process.hrtime.bigint();
  for (let i = 0; i < n; i++) fn();
  return Number(process.hrtime.bigint() - start) / n;
}

console.log('=== differs early:', time(() => secret === wrongEarly).toFixed(2), 'ns');
console.log('=== differs late :', time(() => secret === wrongLate).toFixed(2), 'ns');

const a = Buffer.from(secret), e = Buffer.from(wrongEarly), l = Buffer.from(wrongLate);
console.log('safe early:', time(() => timingSafeEqual(a, e)).toFixed(2), 'ns');
console.log('safe late :', time(() => timingSafeEqual(a, l)).toFixed(2), 'ns');
```

The differences are tiny and noisy locally, but over a network with many samples they are measurable. `timingSafeEqual` takes the same time regardless of where the mismatch is.

### 6. Digital signatures with Ed25519

```js
// signatures.js
import { generateKeyPairSync, sign, verify } from 'node:crypto';

const { publicKey, privateKey } = generateKeyPairSync('ed25519');
const message = Buffer.from('release v1.2.3 sha256=abc123');

const signature = sign(null, message, privateKey);          // Ed25519 takes no digest algorithm
console.log('signature (base64):', signature.toString('base64'));
console.log('verifies:', verify(null, message, publicKey, signature));
console.log('tampered:', verify(null, Buffer.from('release v6.6.6'), publicKey, signature));
console.log(publicKey.export({ type: 'spki', format: 'pem' }));
```

Unlike HMAC, anyone with the **public** key can verify, but only the private key holder can sign.
