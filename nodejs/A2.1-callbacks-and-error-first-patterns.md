## Goal
Understand Node's original async style — error-first callbacks — well enough to use, write, and convert callback APIs correctly.

## Background

### The error-first convention
Node's core APIs were designed before promises existed. Async functions take a callback as their **last** argument, and that callback receives an **error as its first argument**:

```js
fs.readFile(path, 'utf8', (err, data) => {
  if (err) return handle(err);
  use(data);
});
```

If the operation succeeded, `err` is `null` (or `undefined`). If it failed, `err` is an `Error` and the result arguments are meaningless. Always check `err` first.

### Why you can't `try/catch` an async error
`try/catch` only catches errors thrown **synchronously** while the `try` block is running. The callback runs later, on a fresh call stack, after the `try` block has finished. Errors must therefore be passed as values — that's what the first argument is for.

### Rules for writing callback APIs
1. **Call the callback exactly once.** Calling it twice (e.g. once with an error and once with a result) causes bizarre bugs. Use `return callback(err)` so execution stops.
2. **Always call it asynchronously.** If a function sometimes calls back synchronously (e.g. on a cache hit) and sometimes asynchronously, callers can't reason about ordering — this is called "releasing Zalgo". Use `process.nextTick` or `queueMicrotask` to defer synchronous results.
3. **Never throw from an async function — pass the error to the callback.**
4. **Don't throw inside the callback you were given** without understanding where it goes: it will crash the process as an uncaught exception.

### Callback hell
Sequential async steps nest deeper and deeper, error handling is duplicated at every level, and running things in parallel requires manual counters. This "pyramid of doom" is what promises and async/await solve.

### `util.promisify`
`util.promisify(fn)` converts any error-first callback function into one that returns a promise. Most core modules already have promise versions (`node:fs/promises`, `node:timers/promises`, `node:dns/promises`, `node:stream/promises`); use those when available. `util.callbackify` does the reverse.

readFile('data.json', 'utf8', (err, text) => {

### 3. Write a callback API correctly

```js
// cache.js
import { readFile } from 'node:fs';

const cache = new Map();

export function readCached(path, callback) {
  if (cache.has(path)) {
    // Defer so the callback is ALWAYS async (don't release Zalgo)
    process.nextTick(callback, null, cache.get(path));
    return;
  }
  readFile(path, 'utf8', (err, data) => {
    if (err) return callback(err);   // `return` guarantees a single call
    cache.set(path, data);
    callback(null, data);
  });
}
```

```js
// use-cache.js
import { readCached } from './cache.js';

readCached('data.json', (err, first) => {
  if (err) throw err;
  console.log('A: first read');
  readCached('data.json', (err2) => {
    if (err2) throw err2;
    console.log('C: cached read callback');
  });
  console.log('B: after cached call');   // must print before C
});
```

Remove the `process.nextTick` and use `return callback(null, cache.get(path))` instead. What changes in the output order, and why is that dangerous?

### 4. Experience callback hell

```js
// hell.js
import { readFile, writeFile, mkdir } from 'node:fs';

mkdir('out', { recursive: true }, (err) => {
  if (err) return console.error(err);
  readFile('data.json', 'utf8', (err, text) => {
    if (err) return console.error(err);
    const { users } = JSON.parse(text);
    writeFile('out/count.txt', String(users.length), (err) => {
      if (err) return console.error(err);
      readFile('out/count.txt', 'utf8', (err, count) => {
        if (err) return console.error(err);
        console.log('wrote and re-read count:', count);
      });
    });
  });
});
```

### 5. Run callbacks in parallel by hand

```js
// parallel.js
import { stat } from 'node:fs';

function statAll(paths, callback) {
  const results = new Array(paths.length);
  let pending = paths.length;
  let finished = false;

  paths.forEach((p, i) => {
    stat(p, (err, s) => {
      if (finished) return;
      if (err) { finished = true; return callback(err); }
      results[i] = { path: p, size: s.size };
      if (--pending === 0) { finished = true; callback(null, results); }
    });
  });
}

statAll(['data.json', 'package.json', 'hell.js'], (err, results) => {
  if (err) return console.error('failed:', err.message);
  console.table(results);
});
```

Note how much bookkeeping (`pending`, `finished`, preserving order) is needed. `Promise.all` does all of this for you.

### 6. Promisify

```js
// promisified.js
import { promisify } from 'node:util';
import { readFile } from 'node:fs';
import { mkdir, writeFile, readFile as rf } from 'node:fs/promises';
import { readCached } from './cache.js';

const readFileAsync = promisify(readFile);
const readCachedAsync = promisify(readCached);

const text = await readFileAsync('data.json', 'utf8');
console.log(JSON.parse(text).users);

console.log((await readCachedAsync('data.json')).length);

// Rewrite hell.js in 4 lines using the built-in promise API:
await mkdir('out', { recursive: true });
const { users } = JSON.parse(await rf('data.json', 'utf8'));
await writeFile('out/count.txt', String(users.length));
console.log('count:', await rf('out/count.txt', 'utf8'));
```
