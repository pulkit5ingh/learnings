# A7.4 — Error Handling & Diagnostics

**Phase:** 7 — Testing & Debugging
**Topic:** Error classes, `cause`, `AggregateError`, operational vs programmer errors, `uncaughtException`, `unhandledRejection`, stack traces, diagnostic reports
**Type:** Assignment

---

## Goal
Design error handling for a Node service: throw meaningful errors, preserve context as they propagate, recover from the recoverable, crash safely on the rest, and collect enough diagnostics to fix problems after the fact.

## Background

### Throw `Error` objects — always
Throwing strings or plain objects loses the stack trace. Subclass `Error` to add a stable `name` and `code` that callers can branch on, because messages change while codes shouldn't.

```js
class NotFoundError extends Error {
  name = 'NotFoundError';
  code = 'E_NOT_FOUND';
}
```

### Preserve context with `cause`
When you catch a low-level error and rethrow a higher-level one, attach the original: `throw new Error('failed to load config', { cause: err })`. Node prints the whole chain, so you can see both "what we were doing" and "what actually failed". `AggregateError` holds several errors at once (e.g. from `Promise.any`).

### Operational vs programmer errors
- **Operational**: expected failures in correct code — invalid input, file missing, network timeout, DB unavailable. Handle them: retry, fall back, or return a clear error to the caller.
- **Programmer**: bugs — `undefined is not a function`, wrong types, broken invariants. You can't meaningfully recover: the program is in an unknown state. Log loudly and let the process crash; a supervisor (Docker, Kubernetes, systemd, PM2) restarts it.

### Process-level safety nets
- `process.on('uncaughtException', …)` — a synchronous throw nobody caught. After this, the process state is suspect. **Log, flush, and exit** — don't keep serving.
- `process.on('unhandledRejection', …)` — a rejected promise nobody handled. Since Node 15 this crashes the process by default (`--unhandled-rejections=throw`). Treat it like an uncaught exception.
- `process.on('warning', …)` — deprecations and things like `MaxListenersExceededWarning`.

### Stack traces
`Error.captureStackTrace(this, Constructor)` hides internal frames; `Error.stackTraceLimit = 50` shows deeper stacks; `--enable-source-maps` maps traces from compiled TypeScript back to the source.

### Diagnostic reports
`node --report-on-fatalerror --report-uncaught-exception --report-directory=./reports app.js` writes a JSON report with the JS and native stacks, heap stats, resource usage, open handles, environment, and loaded libraries when something goes badly wrong. `process.report.writeReport()` produces one on demand.

```js
// errors.js
export class AppError extends Error {
  constructor(message, { code = 'E_APP', status = 500, details, cause } = {}) {
    super(message, { cause });
    this.name = new.target.name;
    this.code = code;
    this.status = status;
    this.details = details;
    this.expose = status < 500;        // safe to show the message to clients?
  }
}
export class ValidationError extends AppError {
  constructor(details) { super('validation failed', { code: 'E_VALIDATION', status: 422, details }); }
}
export class NotFoundError extends AppError {
  constructor(what) { super(`${what} not found`, { code: 'E_NOT_FOUND', status: 404 }); }
}
export class UpstreamError extends AppError {
  constructor(service, cause) { super(`${service} unavailable`, { code: 'E_UPSTREAM', status: 503, cause }); }
}
```

```js
// use-errors.js
import { readFile } from 'node:fs/promises';
import { AppError, NotFoundError, UpstreamError } from './errors.js';

async function loadConfig(path) {
  try {
    return JSON.parse(await readFile(path, 'utf8'));
  } catch (err) {
    throw new AppError(`could not load config from ${path}`, { code: 'E_CONFIG', cause: err });
  }
}

try {
  await loadConfig('missing.json');
} catch (err) {
  console.log(err.name, err.code, '| cause:', err.cause.code);
  console.error(err);                       // prints the full chain including [cause]
}

const e = new NotFoundError('user 42');
console.log(e instanceof NotFoundError, e instanceof AppError, e instanceof Error, e.status, e.expose);
console.log(new UpstreamError('payments', new Error('ECONNREFUSED')).cause.message);
```

### 2. Map errors to responses in one place

```js
// to-response.js
import { AppError } from './errors.js';

export function toResponse(err, requestId) {
  if (err instanceof AppError && err.expose) {
    return { status: err.status, body: { error: { code: err.code, message: err.message, details: err.details, requestId } } };
  }
  // Unknown or 5xx error: log everything, reveal nothing
  console.error(JSON.stringify({ level: 'error', requestId, name: err.name, message: err.message, stack: err.stack, cause: err.cause?.message }));
  return { status: err.status ?? 500, body: { error: { code: err.code ?? 'E_INTERNAL', message: 'internal server error', requestId } } };
}
```

Call it with a `ValidationError`, an `UpstreamError`, and a `TypeError` and compare what the client would see vs what is logged.

### 3. AggregateError and partial failure

```js
// aggregate.js
const mirrors = [
  () => Promise.reject(new Error('mirror A timeout')),
  () => Promise.reject(new Error('mirror B 503')),
];

try {
  await Promise.any(mirrors.map((m) => m()));
} catch (err) {
  console.log(err instanceof AggregateError, err.errors.map((e) => e.message));
}

// Partial success: allSettled, then decide
const results = await Promise.allSettled([Promise.resolve('ok'), Promise.reject(new Error('bad'))]);
const failures = results.filter((r) => r.status === 'rejected').map((r) => r.reason);
if (failures.length) console.log(new AggregateError(failures, `${failures.length} of ${results.length} jobs failed`).message);
```

### 4. Process-level handlers that exit safely

```js
// crash-safety.js
import { createServer } from 'node:http';

const server = createServer((req, res) => {
  if (req.url === '/throw') setTimeout(() => { throw new Error('bug in a timer'); });
  if (req.url === '/reject') Promise.reject(new Error('forgotten promise'));
  res.end('ok\n');
}).listen(3000);

function fatal(kind, err) {
  console.error(JSON.stringify({ level: 'fatal', kind, message: err?.message, stack: err?.stack }));
  server.close();                                      // stop taking new requests
  setTimeout(() => process.exit(1), 1000).unref();     // give in-flight requests a moment, then exit
}

process.on('uncaughtException', (err) => fatal('uncaughtException', err));
process.on('unhandledRejection', (reason) => fatal('unhandledRejection', reason));
process.on('warning', (w) => console.warn(JSON.stringify({ level: 'warn', name: w.name, message: w.message })));
```

```bash
node crash-safety.js & sleep 0.5
curl localhost:3000/throw; sleep 2; curl localhost:3000/     # connection refused: process exited
```

Write a sentence explaining why `process.on('uncaughtException', () => {})` that just keeps running is dangerous.

### 5. Better stack traces

```js
// stacks.js
Error.stackTraceLimit = 30;

class ParseError extends Error {
  constructor(msg) {
    super(msg);
    this.name = 'ParseError';
    Error.captureStackTrace(this, ParseError);        // omit the constructor frame
  }
}

async function level3() { await null; throw new ParseError('unexpected token at 1:7'); }
async function level2() { await level3(); }
async function level1() { await level2(); }

try { await level1(); } catch (err) { console.log(err.stack); }   // async frames level1 → level3 are visible
```
