## Goal
Build well-behaved command-line programs: parse arguments, read input, write output to the right stream, and exit with meaningful codes.

## Background

### The `process` object
`process` is a global EventEmitter that represents the running Node process:

- `process.argv` — array of command-line arguments. `[0]` is the node binary, `[1]` is the script path, the rest are user arguments.
- `process.env` — environment variables (all values are **strings**).
- `process.cwd()` — the directory the user ran the command from (not the script's directory).
- `process.exitCode` — the code the process will exit with when it finishes naturally.
- `process.exit(code)` — exit **immediately**, abandoning pending async work (and possibly unflushed output).
- `process.stdin`, `process.stdout`, `process.stderr` — standard streams.
- `process.pid`, `process.platform`, `process.memoryUsage()`, `process.uptime()`.

### Exit codes
By convention `0` means success and anything else means failure. Shells, CI systems, and scripts rely on this (`cmd && next` only runs `next` if `cmd` exited 0). Prefer setting `process.exitCode = 1` and letting the process finish over calling `process.exit(1)`, which can cut off output still being written.

### stdout vs stderr
Write **results** to stdout and **diagnostics** (errors, progress, warnings) to stderr. This lets users pipe your program's output (`mytool | jq`) without errors mixed in. `console.log` writes to stdout; `console.error` writes to stderr.

### Parsing arguments with `util.parseArgs`
Node ships a built-in argument parser (stable since Node 20). It supports long and short options, booleans and strings, defaults, multiple values, and positionals — enough for most CLIs without a dependency.

### Interactive input
`node:readline/promises` gives you `rl.question()` with async/await. You can also iterate `rl` line by line to process piped input. Check `process.stdin.isTTY` to know whether a human is typing or input is piped.

### Signals
`process.on('SIGINT', …)` handles Ctrl+C. By default Node exits on SIGINT; once you add a listener, you are responsible for exiting.

### 2. Parse arguments properly

```js
// greet.js
import { parseArgs } from 'node:util';

const { values, positionals } = parseArgs({
  options: {
    name:    { type: 'string', short: 'n', default: 'world' },
    shout:   { type: 'boolean', short: 's', default: false },
    repeat:  { type: 'string', short: 'r', default: '1' },
    help:    { type: 'boolean', short: 'h' },
  },
  allowPositionals: true,
});

if (values.help) {
  console.log('Usage: node greet.js [--name NAME] [--shout] [--repeat N]');
  process.exit(0);
}

const times = Number.parseInt(values.repeat, 10);
if (!Number.isInteger(times) || times < 1) {
  console.error(`error: --repeat must be a positive integer, got "${values.repeat}"`);
  process.exitCode = 2;
} else {
  let msg = `Hello, ${values.name}!`;
  if (values.shout) msg = msg.toUpperCase();
  for (let i = 0; i < times; i++) console.log(msg);
  if (positionals.length) console.error('ignored extra args:', positionals);
}
```

```bash
node greet.js -n Ada -s -r 2
node greet.js --repeat abc; echo "exit code: $?"
node greet.js --unknown        # parseArgs throws on unknown options
```

### 4. Read piped input line by line

```js
// upper.js
import { createInterface } from 'node:readline';

if (process.stdin.isTTY) {
  console.error('Pipe some text in: echo hi | node upper.js');
  process.exitCode = 1;
} else {
  const rl = createInterface({ input: process.stdin });
  let count = 0;
  for await (const line of rl) {
    count++;
    console.log(line.toUpperCase());
  }
  console.error(`processed ${count} lines`);
}
```

```bash
printf "one\ntwo\nthree\n" | node upper.js
cat package.json | node upper.js
```

### 5. Ask interactive questions

```js
// ask.js
import { createInterface } from 'node:readline/promises';
import { stdin as input, stdout as output } from 'node:process';

const rl = createInterface({ input, output });
const name = await rl.question('What is your name? ');
const answer = await rl.question(`Continue, ${name}? (y/N) `);
rl.close();

if (answer.trim().toLowerCase() !== 'y') {
  console.error('aborted');
  process.exitCode = 1;
} else {
  console.log('continuing…');
}
```

### 6. Handle Ctrl+C gracefully

```js
// long.js
let ticks = 0;
const timer = setInterval(() => console.log('working…', ++ticks), 500);

process.on('SIGINT', () => {
  console.error(`\ninterrupted after ${ticks} ticks, cleaning up`);
  clearInterval(timer);
  process.exitCode = 130; // 128 + SIGINT(2), the shell convention
});
```

Run it and press Ctrl+C. Because the interval is cleared, the event loop empties and the process exits on its own with code 130.
