## Goal
Understand Node's two module systems, how Node decides which one a file uses, and how to make them work together.

## Background

### Two module systems
**CommonJS (CJS)** is Node's original system: `require()` to import, `module.exports` to export. `require` is synchronous — it reads, wraps, and executes the file immediately and caches the result.

**ES Modules (ESM)** is the JavaScript standard: `import` / `export`. Imports are **static** (analysed before the code runs), loading is asynchronous, and top-level `await` is allowed. ESM is the modern default and what this curriculum uses.

### How Node decides
| File | Treated as |
|------|-----------|
| `.mjs` | Always ESM |
| `.cjs` | Always CommonJS |
| `.js` with `"type": "module"` in the nearest `package.json` | ESM |
| `.js` without it (or `"type": "commonjs"`) | CommonJS |

Recent Node versions can also detect ESM syntax in ambiguous `.js` files, but always set `"type"` explicitly — explicit is predictable.

### Key ESM differences
- **File extensions are required** for relative imports: `import x from './utils.js'`.
- **No `require`, `module`, `exports`, `__filename`, `__dirname`.** Use `import.meta.filename` and `import.meta.dirname` (Node 20.11+), or `fileURLToPath(import.meta.url)`.
- **Bindings are live**: if a module changes an exported `let`, importers see the new value. CJS exports are copies of values at the time of `require`.
- `this` at the top level is `undefined` (in CJS it is `module.exports`).

### The `node:` prefix
`import fs from 'node:fs'` makes it unambiguous that you mean the built-in, not an npm package called `fs`. Always use it.

### Interop
- **ESM importing CJS** works: `module.exports` becomes the default export, and Node tries to detect named exports.
- **CJS loading ESM**: historically only via dynamic `import()` (which returns a promise). Newer Node versions (22.12+/20.19+) also support `require()` of synchronous ESM graphs, but dynamic `import()` works everywhere.

### Resolution of bare specifiers
`import express from 'express'` walks up the directory tree looking in each `node_modules/` folder. Inside the package, its `package.json` `"exports"` field decides which file is loaded (covered in A8.4).

## Tasks

### 1. CommonJS basics

```bash
mkdir a1-2-modules && cd a1-2-modules
mkdir cjs esm
```

```js
// cjs/math.cjs
function add(a, b) { return a + b; }
let counter = 0;
function increment() { counter++; }
module.exports = { add, counter, increment };
```

```js
// cjs/main.cjs
const { add, increment } = require('./math.cjs');
const math = require('./math.cjs');

console.log(add(2, 3));          // 5
increment();
console.log(math.counter);       // 0 — the exported value was copied
console.log(require.cache[require.resolve('./math.cjs')] !== undefined); // cached
console.log(__dirname);
```

```bash
node cjs/main.cjs
```

### 2. ES Modules basics

```js
// esm/math.js
export function add(a, b) { return a + b; }
export let counter = 0;
export function increment() { counter++; }
export default function multiply(a, b) { return a * b; }
```

```js
// esm/main.js
import multiply, { add, counter, increment } from './math.js';
import * as math from './math.js';

console.log(add(2, 3), multiply(2, 3));
increment();
console.log(counter);            // 1 — live binding
console.log(math.counter);       // 1
console.log(import.meta.filename);
console.log(import.meta.dirname);
```

```json
// esm/package.json
{ "type": "module" }
```

```bash
node esm/main.js
```

### 3. Top-level await and dynamic import

```js
// esm/config.js
import { readFile } from 'node:fs/promises';

// top-level await: the importing module waits for this to finish
const raw = await readFile(new URL('./config.json', import.meta.url), 'utf8');
export const config = JSON.parse(raw);
```

```json
// esm/config.json
{ "port": 3000, "env": "development" }
```

```js
// esm/lazy.js
const lang = process.argv[2] ?? 'en';

// dynamic import: load a module chosen at runtime
const { greeting } = await import(`./greetings/${lang}.js`);
console.log(greeting);
```

Create `esm/greetings/en.js` (`export const greeting = 'Hello';`) and `esm/greetings/fr.js` (`export const greeting = 'Bonjour';`), then run `node esm/lazy.js fr`.

### 4. Importing JSON

```js
// esm/json.js
import pkg from './package.json' with { type: 'json' };
console.log(pkg.type);
```

The `with { type: 'json' }` import attribute is required for JSON in ESM.

### 5. Interop in both directions

```js
// esm/use-cjs.js — ESM importing CJS
import math from '../cjs/math.cjs';
console.log(math.add(1, 1));
```

```js
// cjs/use-esm.cjs — CJS loading ESM via dynamic import
(async () => {
  const { add } = await import('../esm/math.js');
  console.log(add(10, 5));
})();
```

### 6. Break it on purpose
- Remove `.js` from an import in `esm/main.js` — read the `ERR_MODULE_NOT_FOUND` message.
- Use `__dirname` inside `esm/main.js` — read the `ReferenceError`.
- Remove `"type": "module"` from `esm/package.json` and run `esm/main.js` — read the `SyntaxError`.
