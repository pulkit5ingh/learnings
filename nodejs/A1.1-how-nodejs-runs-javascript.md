## Goal
Understand what Node.js actually is — a JavaScript engine plus an async I/O library plus a standard library — and get fluent with the `node` command.

## Background

### Node.js = V8 + libuv + bindings
Node.js is not a language and not a framework. It is a **runtime**: a program that executes JavaScript outside the browser. It has three main parts:

- **V8** — Google's JavaScript engine (also used in Chrome). It parses your code, compiles it to machine code with a JIT compiler, and manages memory with a garbage collector. V8 knows nothing about files or networks.
- **libuv** — a C library that provides the **event loop** and asynchronous I/O. Network sockets use the OS's non-blocking APIs (epoll, kqueue, IOCP). File system operations, DNS lookups, and some crypto run on libuv's **thread pool** (4 threads by default, `UV_THREADPOOL_SIZE` to change).
- **Bindings + standard library** — C++ glue and JavaScript modules (`node:fs`, `node:http`, `node:crypto`…) that expose libuv and OS features to your code.

### Single-threaded, non-blocking
Your JavaScript runs on **one main thread**. When you call `fs.readFile`, Node hands the work to libuv and immediately continues running your code. When the file is ready, libuv queues a callback, and the event loop runs it once the main thread is free. This is why one Node process can handle thousands of concurrent connections: it never sits idle waiting for I/O.

The flip side: **CPU-heavy JavaScript blocks everything.** A 2-second loop means no timers fire and no requests are answered for 2 seconds.

### Browser vs Node globals
Node has no `window` or `document`. It has `globalThis`, `process`, `Buffer`, and — since Node 18 — many web-standard APIs: `fetch`, `URL`, `AbortController`, `TextEncoder`, `structuredClone`, `setTimeout`, `crypto.randomUUID()`.

### Useful CLI flags
| Flag | Purpose |
|------|---------|
| `node file.js` | Run a file |
| `node` | Start the REPL |
| `node -e "code"` / `-p "expr"` | Evaluate / print an expression |
| `node --watch file.js` | Restart on file changes (stable since Node 22) |
| `node --env-file=.env file.js` | Load environment variables from a file |
| `node --inspect file.js` | Enable the debugger (Phase 7) |
| `node --v8-options` | List V8 flags |

### 3. Prove non-blocking I/O

```js
// nonblocking.js
import { readFile } from 'node:fs';

console.log('1. start');

readFile(import.meta.filename, 'utf8', (err, data) => {
  if (err) throw err;
  console.log('3. file read, length =', data.length);
});

console.log('2. readFile called — not waiting for it');
```

```bash
node nonblocking.js
```

Before running, predict the order of the three logs.

### 4. Prove that CPU work blocks

```js
// blocking.js
const start = Date.now();

setTimeout(() => {
  console.log(`timer fired after ${Date.now() - start}ms (expected ~10ms)`);
}, 10);

// Busy-wait for 2 seconds on the main thread
while (Date.now() - start < 2000) {}
console.log('loop finished');
```

The timer fires after ~2000 ms, not 10 ms. Nothing can run while the main thread is busy.

### 5. Observe the thread pool

```js
// threadpool.js
import { pbkdf2 } from 'node:crypto';

const start = Date.now();
for (let i = 1; i <= 6; i++) {
  pbkdf2('secret', 'salt', 200_000, 64, 'sha512', () => {
    console.log(`hash ${i} done at ${Date.now() - start}ms`);
  });
}
```

```bash
node threadpool.js
UV_THREADPOOL_SIZE=6 node threadpool.js
```

With the default pool of 4, hashes 5 and 6 finish noticeably later — they waited for a free thread. With 6 threads they all finish together (if you have ≥ 6 cores).
